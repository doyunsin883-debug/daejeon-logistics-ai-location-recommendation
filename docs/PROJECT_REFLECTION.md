# 프로젝트 회고

## 공모전 문제의식

이번 프로젝트는 "대전 물류데이터 AI 활용 및 분석 아이디어 공모전"을 준비하면서, 생활물류 거점 입지를 데이터로 설명할 수 있는지 확인하기 위해 시작했다.  
단순히 물류센터를 크게 짓는 관점이 아니라, 행정동 단위에서 생활물류 수요가 높고 기존 공급이 부족한 지역을 찾아보는 문제로 접근했다.

산업공학 전공 관점에서는 이 프로젝트를 다음 문제로 볼 수 있다.

- 물류 네트워크 설계 문제
- 시설 입지 선정 문제
- 다기준 의사결정 문제
- 수요-공급 불균형 분석 문제
- 데이터 기반 의사결정 지원 시스템 설계 문제

## 분석 과정에서 좋았던 점

공공데이터만으로도 지역 단위 물류 문제를 어느 정도 설명할 수 있었다.  
인구, 공동주택 세대수, 기존 우체국 수를 결합하니 "어디가 생활물류 거점 후보지로 우선 검토될 수 있는가"를 행정동 단위로 비교할 수 있었다.

특히 Streamlit 대시보드로 만들면서 분석 결과가 표에만 머무르지 않았다.  
지도, 후보지 순위, 군집분석, 가중치 조절을 한 화면에서 보여주니 비전공자도 결과를 이해하기 쉬운 형태가 되었다.

또한 가중치를 조절할 수 있게 만든 점이 좋았다.  
정책이나 사업 목적에 따라 인구 수요를 더 볼 수도 있고, 공동주택 세대수를 더 중요하게 볼 수도 있고, 기존 공급 부족을 더 강하게 반영할 수도 있다.  
이 점은 산업공학의 의사결정 지원 시스템 관점과 잘 맞았다.

## 분석하면서 어려웠던 점

### 1. 데이터 인코딩 문제

공공데이터 CSV는 `utf-8`, `utf-8-sig`, `cp949`, `euc-kr`이 섞여 있었다.  
처음에는 파일마다 인코딩 오류가 발생해서 데이터 로딩 단계부터 막혔다.  
결국 여러 인코딩을 순차적으로 시도하는 `read_csv_auto` 함수를 만들어 해결했다.

### 2. 구별 공동주택 데이터 구조 차이

동구, 서구, 유성구, 대덕구, 중구 공동주택 데이터는 모두 비슷한 주제를 다루지만 컬럼명이 달랐다.  
어떤 파일은 `공동주택명`, 어떤 파일은 `아파트단지명`, 어떤 파일은 주소 컬럼명이 달랐다.  
그래서 구별 데이터를 바로 합칠 수 없었고, 표준 컬럼명으로 바꾸는 전처리 과정이 필요했다.

### 3. 주소와 행정동 매칭 한계

공동주택 데이터의 주소가 법정동, 도로명주소, 지번주소 형태로 섞여 있었다.  
행정동 단위 분석을 하려면 주소를 행정동으로 매칭해야 하는데, 주소 문자열만으로는 정확도가 떨어지는 경우가 있었다.  
이 때문에 일부 행정동의 공동주택 세대수가 과소 추정될 가능성이 있다.

### 4. 행정동 경계 데이터 용량 문제

SGIS 경계 데이터는 shp 파일과 부속 파일이 많고 용량도 컸다.  
GitHub에 원본을 그대로 올리면 저장소가 무거워지고, 100MB를 넘는 파일은 업로드 제한에 걸릴 수 있다.  
그래서 public repo에는 원본 경계 파일을 제외하고, 대시보드에 필요한 정제 GeoJSON만 포함하는 방향이 적절하다고 판단했다.

### 5. K-Means 군집 해석 문제

K-Means는 군집 번호를 0, 1, 2처럼 부여하지만 이 숫자 자체에는 의미가 없다.  
처음에는 군집 번호를 그대로 보여주면 사용자가 해석하기 어렵다고 느꼈다.  
그래서 군집별 평균 입지점수를 기준으로 `최우선 후보군`, `유망 후보군`, `관찰 후보군`, `보완 검토군`처럼 해석 가능한 이름을 붙였다.

### 6. Streamlit 경로 문제

노트북, 분석 스크립트, Streamlit 앱을 실행하는 위치가 다르면 파일 경로가 달라질 수 있었다.  
`Path(__file__).resolve().parent`, `Path.cwd()`, `data/processed` 후보 경로를 함께 탐색하도록 만들어 실행 위치 차이를 줄였다.

## 사용한 기술과 배운 점

| 영역 | 사용 기술 | 배운 점 |
| --- | --- | --- |
| 데이터 전처리 | pandas | 서로 다른 공공데이터를 하나의 분석 단위로 맞추는 과정이 가장 중요했다. |
| 공간 데이터 | GeoPandas, GeoJSON | 좌표계와 행정동 경계 매칭이 지도 시각화의 핵심이었다. |
| 머신러닝 | K-Means, StandardScaler | 군집분석은 결과보다 해석 가능한 이름을 붙이는 과정이 중요했다. |
| 시각화 | Streamlit, Plotly, PyDeck | 분석 결과는 대시보드로 만들 때 설득력이 크게 올라갔다. |
| 산업공학 | 입지분석, 다기준 의사결정 | 현실 문제를 수요, 공급, 비용, 제약 조건으로 나누어 보는 관점이 도움이 되었다. |

## 현재 모델의 한계

- 실제 택배 배송량을 행정동 단위로 직접 반영하지 못했다.
- 공동주택 세대수는 수요를 설명하는 proxy일 뿐, 실제 물동량과 완전히 같지 않다.
- 기존 공급을 우체국 수로 단순화했기 때문에 민간 택배 거점, 편의점 택배, 물류센터 접근성은 반영하지 못했다.
- 도로 접근성, 지가, 임대료, 부지 확보 가능성, 규제 조건이 빠져 있다.
- 행정동 내부의 세부 위치까지 추천하는 모델은 아니며, 행정동 단위 우선순위 모델에 가깝다.

## 개선 아이디어

1. 주소 정제와 지오코딩을 적용해 공동주택의 행정동 매칭률을 높인다.
2. 도로망, 교통량, 상권, 유동인구 데이터를 결합한다.
3. 우체국뿐 아니라 편의점 택배, 민간 물류 거점, 물류창고 접근성을 반영한다.
4. 후보지 선정에 비용, 부지 면적, 도로 접근성 같은 현실 제약을 추가한다.
5. K-Means 외에 DBSCAN, Gaussian Mixture, 계층적 군집분석을 비교한다.
6. 점수 산식을 고정하지 않고 AHP 또는 엔트로피 가중치 방식과 비교한다.

## 공모전 발표에서 강조하면 좋은 포인트

- 문제 정의가 명확하다: "생활물류 수요는 증가하는데, 행정동별 공급 우선순위는 직관적으로 보기 어렵다."
- 산업공학적이다: 수요, 공급, 입지, 의사결정, 시각화를 하나의 시스템으로 연결했다.
- 구현 결과가 있다: 노트북 분석에서 끝나지 않고 Streamlit 대시보드로 확인 가능하다.
- public repo 전략이 안전하다: 원본 데이터는 재배포하지 않고 출처와 재현 방법을 명시했다.
- 확장성이 있다: 도로망, 비용, 민간 물류망을 추가하면 실제 정책/사업 검토 도구로 발전시킬 수 있다.
